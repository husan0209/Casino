# TECH_DEBT — реестр архитектурного долга под храповиком

> Статус: заведён 2026-09-27, переснят 2026-10-03 по базе `8efcc25` с учётом
> #137–#141 (см. легенду знака † перед таблицей реестра). Правила архитектуры
> включены в error, но СУЩЕСТВУЮЩИЙ долг заморожен в базлайнах — CI краснеет,
> если долг ВЫРОС (FAIL, exit 1) или если он погашен, а базлайн не ужат
> (STALE, exit 3). Так новый код чист с первого дня, а старый гасится
> постепенно, без красного CI.

## Как работает храповик

- Детектор один: `scripts/bin/tech-debt` (gen — перезаписать базлайн, check — сверить,
  list — имена правил). Имя правила проверяется ДО записи файла: `gen <опечатка>`
  больше не создаёт пустой `tech-debt/<опечатка>.txt` (чинилось в #136).
- Базлайны лежат в `tech-debt/<name>.txt`, формат `путь<TAB>количество`
  (для use-case-specs — путь на строку). Базлайн правится ТОЛЬКО командой gen.
- Гuards CI: G16–G21 и **G24** в `.github/workflows/architecture-guards.yml`
  (каждый — `sh scripts/bin/tech-debt check <name>`). Работоспособность G24
  доказывает G25 (`sh scripts/bin/guard-selftest`, QUALITY_GATES §3.6): тот же
  детектор по temp-дереву с файлом-ловушкой обязан дать ненулевой exit-code.
- Сравнение — числовое, per-file (`diff_state` в `scripts/bin/tech-debt`):
  **FAIL (exit 1)** — факт больше базлайна (новый файл или рост числа нарушений
  в файле); **STALE (exit 3, красит CI)** — факт меньше базлайна: долг погашен,
  ужми его `sh scripts/bin/tech-debt gen <name>` в том же PR; **OK (exit 0)** — равно.
  Переходный прогон без красного CI — `check --allow-stale <name>`.
- Частичный burn-down (в файле было 3, стало 2) — это STALE, а не FAIL: ложный
  «долг вырос» на таком случае убран в #136 (раньше сравнение шло через `comm`).
- Базлайн `0` (пустой файл) превращает ratchet в жёсткий gate: любое новое
  нарушение = FAIL, ужимать дальше некуда. Сейчас на нуле G17, G19, G20, G21.

Замечание к audit-храповику: реестр CVE живёт своей жизнью — если в
транзитивной зависимости появится новый advisory, job покраснеет БЕЗ твоих
изменений. Это осознанно (новый CVE обязан попасть в триаж), а не регресс
храповика: триаж — upgrade / `pnpm.auditOverrides` в package.json / mute,
затем `--gen`. Канарейка полноты отчёта (#140): обрезанный отчёт → rc=2,
новый незаглушённый high → rc=1. Локально на Windows отчёт не переснимать —
в #140 проверено, что «EMFILE урезает prod-отчёт» было легендой, отчёт полный.

Замечания к правилам (осознанные ограничения детекторов; замер 2026-10-03 по базе `8efcc25`):

- G20 не проверяет `total`: в пагинации это счётчик записей, не деньги
  (изначальный «замер на 38» почти весь состоял из таких ложных срабатываний).
  Рядом с правилом, но вне его радиуса: `affiliate/domain/affiliate-settings.ts:45`
  `minDepositRub: number` — порог атрибуции в RUB, не сумма транзакции.
- G16 разрешает импорт `*.facade` — это публичный API модуля. После #141 фасадов
  8 (`git ls-tree -r --name-only origin/feat/referrals-facade … \| grep 'facade/'`):
  `admin`, `affiliate`, `geo`, `kyc`, `payments`, `referrals`, `users`, `wallet` —
  все по шаблону `<mod>/facade/<mod>.facade.ts` (разнобой `application/` vs
  `facade/` устранён: `wallet` переехал в #102, `admin`/`affiliate`/`referrals`
  создавались сразу в `facade/`).
- G16 НЕ считает импорты, оканчивающиеся на `.guard` и `.facade`. Это не «мелкая
  слепота», а оформленное решение В6.1: guard'ы аутентификации = публичный API
  модуля (`AuthGuard`/`RolesGuard`, `AdminAuthGuard`, `AffiliateAuthGuard`).
  Следствие: `kyc-admin.controller.ts:17` → `admin/presentation/admin-auth.guard`
  формально невидим для детектора, его легальность держит текст
  MODULE_BOUNDARIES §13.2.1/§16.2, а не гард.
- G16 не считает модулями `queues/`, `common/` и прочее вне `src/modules/`.
- **G24 (`foreign-writes`)** — карта `MODEL_OWNERS` в `scripts/bin/tech-debt` есть
  источник истины владения; в `MODULE_BOUNDARIES` владение описано словами
  (§3.2, §18.6), и расхождение между ними — правка карты (сначала сверка с
  «кто создаёт строку»), а не подгонка детектора. Слепые пятна правила,
  принятые осознанно: (а) пишутся только строковые вызовы вида
  `<клиент>.<модель>.<метод>(` — алиас `const db = prisma` и перенос вызова
  через строку не ловятся; (б) `queues/`, `common/` и скрипты вне
  `apps/api/src/modules` не сканируются (там нет модуля-владельца, сравнение
  неопределено); (в) спеки, `__tests__/` и `*.mock.ts` исключены — мок чужого
  репозитория не есть запись в чужую таблицу; (г) анти-вакуум: модель схемы без
  владельца в карте (и владелец без модели) = exit 2, а не пустой «OK».

ниже находились в `scripts/bin/tech-debt` и `scripts/audit-ratchet.mjs` и
**устранены**: #136 (база `8efcc25`) и #140 (`fix/cve-overrides`). Оставляем этот

  git попал `tech-debt/gen.txt`, `e07de5f`). **Починено в #136:** имя правила
