## 1. Цель этапа

Собрать публичный веб-клиент, на котором человек с телефона за 10–15 секунд понимает, куда жать, запускает слот и может пополнить нужный кошелёк.

**Приёмка UX** — по сценариям [USER_FLOW_FIRST_90_SECONDS.md](USER_FLOW_FIRST_90_SECONDS.md). Если на шаге человек думает дольше 2 секунд — интерфейс проиграл.

В релиз входят:

- главная и витрина слотов;
- каталог с поиском и фильтрами;
- запуск игры в iframe / fullscreen;
- регистрация, вход, OAuth;
- личный кабинет;
- мультивалютный кошелёк;
- пополнение и вывод: локальный фиат + USDT TRC20 + BTC;
- история транзакций и ставок;
- KYC;
- тикеты поддержки;
- реферальный кабинет;
- UI-система и geo-конфиг.

Не входят в релиз как продукт, но в типах/флагах резервируются:

- бонусный движок, вейджер, промокоды;
- crash / live как отдельные залы;
- внутренний обменник валют;
- отдельные сайты под каждую страну.

## 2. Общие принципы Frontend

### 2.1. Технический стек

```
Next.js 14+          — App Router, SSR/SSG/ISR
TypeScript           — строгая типизация
Tailwind CSS         — стилизация
TanStack Query       — server state
Zustand              — client state (auth, wallet, ui, geo)
React Hook Form      — формы
Zod                  — валидация
Axios                — HTTP клиент
next-themes          — не используем переключатель в релизе, только тёмная тема
```

Socket.IO в этой части не подключать. Баланс на игровом экране обновлять polling / refetch после закрытия игры и по фокусу окна.

### 2.2. Продуктовая рамка

```
Рынок:            СНГ
Трафик:           ~90% мобильный, десктоп обязателен
Ядро релиза:      слоты
Следующие входы:  crash, затем live
Кошельки:         отдельные балансы, без тихой конвертации
Фиат MVP:         RUB
Фиат Phase 2:     UAH, BYN, KZT, UZS (типы и GeoConfig готовы заранее)
Крипта MVP:       USDT TRC20, BTC
Бонусы:           выключены флагами
Бренд:            один фронт, гео меняет кассу и дефолтную валюту
```

> **MVP vs Phase 2:** в MVP живые платежи и кошельки — **RUB + USDT TRC20 + BTC**. UAH / BYN / KZT / UZS заложены в типы, `GeoConfig`, форматирование сумм и UI switcher, но включаются без смены UX, когда бэкенд и PSP подключены для соответствующего гео (см. [tz-part-3](tz-part-3-payments-wallet.md) §3.2).

Ориентир по ощущению:

- каркас и спокойствие как у Stake;
- витрина и касса как у 1win / Pin-Up;
- деньги как в нормальном fintech-приложении, не как в админке.

Не копировать Stake в крипто-логике и не копировать 1win в перегрузе баннерами.

### 2.3. Продуктовые правила UI

1. Телефон — основной клиент. Десктоп повторяет те же сценарии на широкой сетке.
2. На экране одно главное действие. Витрина — запустить слот. Касса — пополнить. Игра — крутить.
3. Деньги всегда в одном месте: активный баланс + зелёная «Пополнить» в шапке.
4. У игрока несколько кошельков, в голове должна быть одна валюта. Список из всех валют не показывают без запроса.
5. Касса не конвертирует. Депозит в тенге падает в KZT. Ставка и вывод — в KZT. USDT остаётся USDT.
6. Кросс-валютная игра запрещена. Нельзя крутить слот в ₸ с кошелька ₽.
7. Память важнее навигации: последняя игра, последний метод, активный кошелёк, последние фильтры.
8. Сначала игра, потом кабинет. KYC / рефералка / сессии не встречаются до первого ценного действия, кроме блокировки вывода или лимита.
9. Ошибка даёт следующий шаг, не тупик.
10. Новичок видит 12 слотов, поиск и одну кассу. RTP, волатильность, провайдеры, история — по запросу.
11. Пункт «Быстрые игры» в меню не создавать. Crash появится отдельным входом, когда будет что открывать. Live — ещё позже.
12. Один бренд и один UI. Не делать разные макеты под RU / KZ / UZ / UA / BY.

### 2.4. Дизайн-концепция

Тёмная тема только.

```
Background primary:   #0F0F1A
Background secondary: #1A1A2E
Background card:      #16213E
Border:               #2A2A4A
Accent primary:       #6C63FF   — бренд, навигация, «Играть»
Accent secondary:     #00D2FF   — редкие акценты, не деньги
Money / Deposit:      #00C853   — только деньги и успех
Error:                #FF3D71
Warning:              #FFB300
Text primary:         #FFFFFF
Text secondary:       #8888AA
```

Правило цвета:

- «Пополнить» и плюс баланса — только зелёные;
- «Играть» — акцентный бренд;
- выигрыш / плюс — зелёный;
- минус / ошибка — красный;
- навигация не должна быть того же цвета, что касса.

Финальные hex может уточнить дизайнер, роли цветов — нет.

### 2.5. Currency & Locale

Игровые валюты (полный продуктовый набор; MVP — см. §2.2):

| Код | Как писать игроку | Символ | Пример в шапке | MVP |
|---|---|---|---|---|
| RUB | руб. | ₽ | `1 200 ₽` | ✅ |
| UAH | грн | ₴ | `500 ₴` | Phase 2 |
| BYN | бр | Br | `50 Br` | Phase 2 |
| KZT | тг | ₸ | `15 000 ₸` | Phase 2 |
| UZS | сум | soʻm | `150 000 soʻm` | Phase 2 |
| USDT | USDT | USDT | `150 USDT` | ✅ |
| BTC | BTC | BTC | `0.0012 BTC` | ✅ |

Правила формата:

- разделитель тысяч — пробел;
- ISO-коды допустимы в кошельке и истории, не в шапке фиата;
- Беларусь — только **BYN**, никогда «белорусский RUB»;
- фиат на витрине без копеек;
- UZS нельзя обрезать и нельзя писать без пробелов;
- USDT в шапке — 2 знака, в кошельке — до 2–6 по факту зачисления;
- BTC в шапке — 4–6 знаков, в кошельке — 8;
- базовая валюта оператора (EUR / USDT reporting) игроку не показывается как главный баланс;
- нельзя суммировать ₽ + ₸ + USDT в одну красивую цифру.

Пресеты депозита только для активной валюты:

- **RUB:** 1 000 / 2 000 / 5 000 / 10 000
- **UAH:** 500 / 1 000 / 2 000 / 5 000
- **BYN:** 30 / 50 / 100 / 200
- **KZT:** 5 000 / 10 000 / 20 000 / 50 000
- **UZS:** 100 000 / 200 000 / 500 000 / 1 000 000
- **USDT:** 20 / 50 / 100 / 200
- **BTC:** пресетов сумм нет, принимаем фактический входящий платёж

Минимумы, максимумы, KYC-остаток — всегда с символом валюты. Голое число в кассе = ошибка реализации.

**KYC-лимит в UI:** бэкенд считает лимит внутренне в RUB-эквиваленте (см. [tz-part-2](tz-part-2-auth-users-kyc-rbac.md) §4, [tz-part-3](tz-part-3-payments-wallet.md) §4), но UI показывает остаток в **активной валюте** кошелька, который сейчас пополняют.

Определение активного кошелька:

1. Есть успешный депозит → валюта последнего депозита.
2. Депозита не было, есть ненулевой кошелёк → он. Ненулевой фиат важнее нулевой крипты.
3. Все нули → валюта страны профиля / IP.
4. Гость → валюта по IP, смена в 1 тап.
5. Выбор пишется в профиль (`currency_preference`) и `localStorage`.

### 2.6. Гео и домены

Один фронт. Страновые домены в этой части не проектируются.

Нужен `BrandConfig` / `GeoConfig`:

```ts
type GeoConfig = {
  hostname: string
  defaultCurrency: 'RUB' | 'UAH' | 'BYN' | 'KZT' | 'UZS'
  enabledFiat: Array<'RUB' | 'UAH' | 'BYN' | 'KZT' | 'UZS'>
  enabledCrypto: Array<'USDT_TRC20' | 'BTC'>
  paymentMethods: PaymentMethod[]
  legalCountry: 'RU' | 'KZ' | 'UZ' | 'UA' | 'BY' | 'INTL'
}
```

Логика:

1. IP задаёт дефолтную валюту и набор методов только для гостя и нового пользователя.
2. Если пользователь уже логинился — важнее его активный кошелёк, не текущий IP.
3. Человек в роуминге с кошельком ₸ видит казахстанскую кассу, не СБП.
4. Смена «страны кассы» = смена активного кошелька. Отдельного глобуса и шага «выберите страну» нет.
5. RU и UA методы никогда не в одном списке.
6. Платёжные иконки в футере и кассе — только доступные этому гео.
7. Зеркала используют тот же фронт и тот же конфиг, отличаться может только hostname.

В MVP `enabledFiat` для RU = `['RUB']`. Остальные фиаты включаются в GeoConfig по мере подключения PSP (Phase 2).

Экран выбора страны допустим только как ручной fallback, если IP определился неверно. Не первый шаг регистрации.

### 2.7. Крипта в UI

Крипта в релизе есть, но это второй рельс, не вторая главная.

- отдельные кошельки `USDT / TRC20` и `BTC`;
- сеть видна всегда;
- без автоконвертации в ₽ / ₸ / ₴ / BYN / UZS;
- без внутреннего обменника;
- ETH, TON, LTC, ERC20 в релизе не открывать;
- если активен фиат, крипта живёт в «Ещё способы»;
- если активен USDT/BTC, касса сразу криптовая;
- игра стартует в крипте только если провайдер принимает эту валюту;
- иначе честный выбор: сыграть с фиатного кошелька или выбрать другую игру.

### 2.8. Бонусы

Бонусного движка в релизе нет.

Флаги:

```
FEATURE_PROMOCODE=false
FEATURE_BONUS_PAGE=false
FEATURE_WAGERING=false
```

Заложить, но не показывать:

- слот под один баннер на главной;
- скрытое поле промокода в DepositSheet;
- опциональное `bonusBalance?` в типах кошелька.

Не рисовать «Бонус: 0 ₽». Не обещать +100%, если начислить некому. Когда бонус появится, он будет только в валюте депозита.

## 3. UI Component System

Минимальная библиотека в `components/ui/`. Каждый компонент — отдельный файл.

### 3.1. Базовые

- **Button** — `primary`, `secondary`, `ghost`, `danger`, `money`. Размеры `sm / md / lg`. Состояния `loading`, `disabled`. `money` — только для пополнить / успешно оплатить.
- **Input** — `default`, `error`, `success`, prefix/suffix.
- **AmountInput** — отдельный ввод денег: маска пробелов, символ валюты, без голого number input.
- **Select**
- **Sheet** — нижняя модалка для телефона. Основной контейнер кассы, логина, switcher валют.
- **Modal / Dialog** — для десктопа и подтверждений.
- **Toast**
- **Skeleton**
- **Badge** — один бейдж на карточку: `NEW` или `HOT`, не оба.
- **Spinner**
- **Avatar**
- **Tabs**
- **Pagination**
- **EmptyState** — всегда с следующим действием, не с пустым текстом.
- **Divider**
- **Tooltip** — только десктоп.
- **ConfirmModal**
- **SearchInput**
- **CurrencyAmount** — единый форматтер суммы.

Модалки логина, депозита, вывода и switcher валют живут в корне `(main)` layout, не внутри страниц. Так они открываются поверх игры и переживают смену роута.

## 4. Layout

### 4.1. Телефон — основной каркас

```
┌─────────────────────────────────┐
│ лого     1 200 ₽   [Пополнить]  │  sticky header
├─────────────────────────────────┤
│ поиск                           │
│ [Слоты] [Популярные] [Новые]    │
├─────────────────────────────────┤
│                                 │
│            CONTENT              │
│                                 │
├─────────────────────────────────┤
│ Главная  Казино  Избр.  Профиль │  bottom nav
└─────────────────────────────────┘
```

Широкий текстовый сайдбар 220px **не является** основной навигацией.

### 4.2. Header

Sticky всегда.

**Гость:** логотип слева, справа `Войти` и акцентная `Регистрация`.

**Свой:**

```
лого        1 200 ₽ ▾     [Пополнить]     [аватар]
```

Тап по сумме открывает `WalletSwitcherSheet`:

```
Кошелёк
✓  1 200 ₽
   8 200 ₸
   150 USDT
   0 ₴
   0 Br
   0 soʻm
   0.00000000 BTC
```

Правила switcher:

- первым активный;
- ненулевые выше нулевых;
- нулевые тусклые, но видимые;
- тап меняет `activeCurrency` и закрывает sheet;
- никакого «итого ≈ 15 400 ₽»;
- USDT всегда с сетью в деталях кошелька, в switcher достаточно `USDT`.

«Пополнить» всегда зелёная, всегда на одном месте, всегда открывает DepositSheet в активной валюте.

На телефоне в шапке нет пунктов «Казино / Live / Провайдеры».

Аватар открывает короткое меню: Профиль, Кошелёк, История, Выйти. KYC показывать в этом меню только если статус мешает лимиту или выводу.

### 4.3. Bottom Navigation

Только `< 768px`:

```
Главная · Казино · Избранное · Профиль
```

Кошелёк в таббар не ставить: он уже в шапке.

Позже, когда появится crash:

```
Главная · Казино · Crash · Профиль
```

Live в таббар не добавлять в этой части.

### 4.4. Поиск

Глобальный, не только внутри каталога.

- телефон: поле под шапкой на главной и отдельный экран `/search`;
- десктоп: поле в хедере + `Ctrl/⌘ K`;
- ищем игры и провайдеров;
- показываем недавние запросы и last played;
- пустой результат — похожие слоты + сброс.

### 4.5. Десктоп

- слева узкая икон-панель 64–72px, подписи по hover/pin;
- не держать постоянно 220px текста;
- поиск в хедере;
- сетка слотов 5–6 колонок;
- баланс и «Пополнить» те же, справа;
- игра в рабочей области, касса оверлеем.

Пункты десктоп-панели в релизе:

```
Главная
Казино
Избранное
Провайдеры
Кошелёк
История
Поддержка
```

Не добавлять заранее Live / Настольные / Быстрые / Бонусы.

### 4.6. Footer

Короткий: логотип, 18+, условия, конфиденциальность, ответственная игра, иконки доступных методов этого гео. На телефоне одна колонка. Не устраивать витрину из 20 логотипов, половина из которых человеку недоступна.

### 4.7. Auth Layout

Центр экрана, логотип, карточка формы, тёмный фон. Без казино-навигации.

## 5. Страницы аутентификации

## 8. Страница игры и launch flow

Маршрут `/casino/[slug]` нужен для SEO, шаринга и информации. Это **не обязательный шлюз** в игру.

### 8.1. Превью страницы

- обложка;
- название, провайдер;
- RTP / волатильность / мин. ставка — здесь, не на карточке витрины;
- кнопки «Играть» и «Демо»;
- избранное;
- похожие слоты.

### 8.2. Контракт запуска

Один и тот же flow с карточки, с превью и с last played. Детали бэкенда — [tz-part-4](tz-part-4-casino-providers.md) §6.

1. Гость → LoginSheet → после входа продолжить launch.
2. Свой, активный кошелёк > 0 и провайдер принимает валюту → сразу игра.
3. Активный = 0, другой кошелёк > 0 → короткий sheet:
   `В ₽ пусто. Играть с 8 200 ₸?`
   Кнопки: `Играть в ₸` / `Пополнить ₽`.
4. Все кошельки пустые → DepositSheet в активной валюте.
5. Провайдер не принимает активную валюту → честный sheet, без тихой конвертации.
6. Повторный заход в ту же игру → сразу последняя валюта, без вопроса.
7. `lastPlayedCurrency` хранить в wallet store / localStorage.

Выбор валюты перед каждым спином запрещён как сценарий по умолчанию.

### 8.3. Игровой экран на телефоне

Полноэкранный режим:

```
×      1 200 ₽     [+]
[          iframe         ]
```

- `+` открывает кассу **поверх** игры;
- после депозита — «Вернуться в игру»;
- баланс на этой планке живой: refetch по фокусу и после закрытия кассы;
- плюс/минус подсвечивать коротко.

На десктопе iframe в рабочей области, та же планка над игрой, fullscreen по кнопке.

### 8.4. Ошибки запуска

Отдельные экраны, не общий toast:

- игра недоступна в регионе;
- провайдер не ответил / timeout;
- сессия уже открыта;
- недостаточно средств;
- валюта не поддерживается;
- техработы провайдера.

После закрытия iframe — `refreshActive()` кошелька.

Demo доступно без авторизации, если провайдер отдаёт demo URL.

## 10. Кошелёк и касса

`/wallet` — страница доверия и списка кошельков.  
Деньги делаются в `DepositSheet` / `WithdrawSheet`.

80% пополнений придут из шапки и из игры, не с `/wallet`.

### 10.1. Модель UI

Отдельные балансы. Никакой автоконвертации. Никакого общего эквивалента крупно.

```
Активный кошелёк
1 200 ₽                 [Пополнить] [Вывести]

Фиат
₸   8 200               [Открыть]
₴       0               [Пополнить]
Br      0
soʻm    0

Крипта
USDT  TRC20   150.00
BTC             0.00000000
```

Тап по другому кошельку делает его активным.  
«Открыть» на ненулевом — активировать.  
«Пополнить» на нулевом — активировать и сразу открыть кассу этой валюты.

Последние 5 транзакций активного кошелька + «Смотреть все».

### 10.2. DepositSheet

Глобальный sheet из шапки, пустого запуска игры и карточки кошелька.

#### Активен фиат

Шаг 1 — методы этой валюты и страны, без развилки «фиат / крипто»:

```
Пополнить ₽                            ✕

СБП                            последний
Карта
P2P
Ещё способы
  USDT TRC20
  BTC
```

Правила:

- последний успешный метод первый;
- методы режутся по гео + валюте;
- казаху не показывать СБП первым;
- крипта не стоит в одном ряду с локальной кассой как равный герой.

Шаг 2 — сумма:

```
Сумма
[ 2 000 ] ₽

[1 000] [2 000] [5 000] [10 000]

Минимум 500 ₽
Без верификации осталось 1 800 ₽
```

Сменили активный кошелёк на KZT — пресеты, минимум, KYC-остаток и методы пересчитываются в ₸.

Поле промокода не показывать, пока `FEATURE_PROMOCODE=false`.

Шаг 3 — переход к PSP в новой вкладке / WebView.  
Polling статуса как в платёжной части. Успех:

```
+2 000 ₽ зачислены
[Вернуться в игру]   или   [Закрыть]
```

После успеха шапка остаётся в этой валюте.

#### Активен USDT / выбран USDT из «Ещё»

```
Пополнить USDT                         ✕

Сеть: TRC20
Отправьте только USDT в сети TRC20

[ QR ]
TXyz...abcd                     [Копировать]

Ожидаем оплату · до 14:35
[Проверить статус]
```

Коротко и жёстко:

- только USDT;
- только TRC20;
- ERC20 на этот адрес = потеря денег.

Зачислять **факт** входящего платежа, не требовать сумму копейка в копейку.

Успех переключает активный кошелёк на USDT, если депозит был в USDT.

#### BTC

Тот же экран: сеть Bitcoin, адрес, QR, факт зачисления, полные 8 знаков в деталях. Пресет суммы не нужен.

### 10.3. WithdrawSheet

Порядок проверок до формы:

1. KYC не approved → стоп и одна кнопка «Пройти верификацию». Без формы карты/адреса.
2. Активный кошелёк пустой и других денег нет → «Нечего выводить».
3. Активный пустой, в другом есть деньги → предложить вывести ту валюту, не открывать нулевую форму.

Вывод только в валюте выбранного кошелька и только на метод этой валюты.  
Не предлагать «выведем рубли на Kaspi, сами конвертируем».

Фиат: сумма, пресеты, реквизиты метода, минимум, срок «до 24 часов», подтверждение.

Крипта: сумма, адрес той же сети, проверка формата до сабмита, сеть сменить нельзя.  
TRC20-адрес не должен проходить валидацию BTC.

KYC-правило вывода одинаковое для фиата и крипты, пока продукт явно не решит иначе.

После создания заявки: номер, статус, «История».

### 10.4. Что касса никогда не делает

- не складывает все кошельки в одну сумму;
- не показывает крупно «≈ 180 $»;
- не конвертирует крипту в рубли «для удобства»;
- не спрашивает валюту, если развилки нет;
- не показывает чужие гео-методы;
- не выкидывает из игры на `/wallet` при нулевом балансе.

## 13. KYC Верификация

Маршрут `/kyc`, protected.

Состояния как продуктовые экраны:

1. Не начата — лимит в **активной** валюте, прогресс, что даст верификация, кнопка начать.
2. Форма — данные + загрузка документа + селфи.
3. На проверке.
4. Нужна повторная отправка + причина.
5. Отклонено + причина + подать заново.
6. Одобрено.

Лимит без KYC нельзя показывать одной строкой «до 5 000 ₽» человеку с активным ₸. API отдаёт `kyc_limit_remaining` в запрошенной валюте; внутренний расчёт — RUB-эквивалент (см. tz-part-2 §4).

KYC не должен вылезать на витрину. Его место: вывод, касса при упоре в лимит, профиль.

interface AuthStore {

  logout(): Promise<void>
  fetchMe(): Promise<void>

### WalletStore

Это ядро UI, не просто список.

```ts
interface WalletStore {
  wallets: WalletBalance[]
  activeCurrency: string
  lastPlayedCurrency: string | null
  lastPaymentMethod: string | null
  isLoading: boolean

  setActiveCurrency(currency: string): Promise<void>  // PATCH /users/me currency_preference
  getActiveWallet(): WalletBalance | undefined
  getNonZeroWallets(): WalletBalance[]
  fetchWallets(): Promise<void>
  refreshActive(): Promise<void>
  applyBalanceDelta(currency: string, delta: number): void
}
```

Правила:

- хедер читает только активный кошелёк;
- смена валюты не перезагружает приложение;
- после депозита/выигрыша обновляется конкретный кошелёк;
- оптимистичное обновление допустимо, с откатом;
- в провайдер уходит валюта активного кошелька, не reporting currency.

Текущий `GeoConfig`, дефолтная валюта гостя, доступные методы.

| Касса | Sheet снизу | Sheet/Modal |
| Сетка слотов | 2 колонки | 5–6 |
| Запуск | fullscreen | iframe + fullscreen |
| Поиск | экран / поле под шапкой | хедер + ⌘K |
| Карточка | тап = игра | hover доп. кнопки |

Тестировать в первую очередь 360–430px. Десктоп не может иметь другой порядок денег.

## 22. Performance

- `next/image`, WebP, blur, lazy thumbnails;
- домены CDN провайдеров сразу в `next.config`;
- виртуализация длинных сеток на телефоне;
- dynamic import iframe и KYC-загрузчика;
- ISR главной 60 секунд;
- кабинет и касса — CSR со скелетонами;
- не тащить платёжные и игровые библиотеки в общий bundle;
- после закрытия игры не держать iframe в памяти.

## 23. Технические задачи Части 5

### Блок A. UI-система

Button включая `money`, Input, AmountInput, CurrencyAmount, Sheet, Modal, Toast, Skeleton, Badge, Spinner, Avatar, Tabs, Pagination, EmptyState, ConfirmModal, SearchInput, Select.

**Приёмка:** компоненты сходятся с цветовыми ролями, Sheet удобен одной рукой, суммы форматируются по всем валютам релиза, включая UZS и BTC.

### Блок B. Layout, geo, валюта

Header в двух состояниях, WalletSwitcher, bottom nav, десктоп икон-панель, footer по гео, GeoConfig, определение дефолтной валюты, запоминание активного кошелька.

**Приёмка:** казаху не показывают СБП первым; залогиненный с ₸ в роуминге не теряет казахстанскую кассу; в шапке одна сумма; нулевые кошельки видны, но тусклые.

### Блок C. Auth

Регистрация, вход, verify, forgot, reset, Google, Telegram, LoginSheet, AuthProvider, middleware.

**Приёмка:** после регистрации можно сразу смотреть слоты и запускать demo/игру по правилам бэка; launch после логина продолжается; письмо не является тупиком.

### Блок D. Витрина и каталог

Главная для гостя и своего, last played, GameCard, поиск, каталог, URL-фильтры, infinite scroll, избранное, страница провайдера.

**Приёмка:** тап по карточке на телефоне запускает игру; нет пустых разделов Live/Быстрые; нет дубля Featured/Популярные; поиск доступен не только из каталога.

### Блок E. Запуск игры

Превью, launch contract, fullscreen, планка баланса, demo, ошибки провайдера, возврат в игру после депозита.

**Приёмка:** нет обязательного выбора валюты; нулевой активный кошелёк предлагает ненулевой; неподдерживаемая валюта не стартует молча; после выхода баланс обновлён.

### Блок F. Профиль

Данные, аватар, пароль, сессии, настройки.

**Приёмка:** сохраняется, сессии завершаются, OAuth-аккаунт не ломается формой пароля.

### Блок G. Кошелёк и платежи

Страница кошельков, DepositSheet фиат, DepositSheet USDT/BTC, polling, WithdrawSheet фиат/крипта, KYC-стопер, история транзакций.

**Приёмка:** фиат падает в свой кошелёк; USDT не превращается в рубли; сеть видна; последний метод первый; пресеты свои у каждой валюты; из игры касса открывается поверх iframe.

### Блок H. KYC, поддержка, рефералы

Все состояния KYC, тикеты, рефералка без GGR-формулировок.

**Приёмка:** лимиты в понятной валюте; тикет создаётся; ссылка копируется.

### Блок I. Stores и API

TanStack Query, AuthStore, WalletStore, UIStore, GeoStore, refresh token, API по доменам.

**Приёмка:** активная валюта переживает reload; 401 обновляет токен; ошибки кассы и запуска не схлопываются в один toast.

## 24. Что НЕ делать в Части 5

- WebSocket как обязательную зависимость релиза;
- мобильное приложение / отдельный native клиент;
- мультиязычность;
- переключатель светлой темы;
- live-чат поддержки;
- push в браузере;
- win-cinematics и тяжёлый сокет-ticker;
- отдельные домены и разные UI под страны;
- экран «выберите страну» как первый шаг;
- автоконвертацию фиата и крипты;
- внутренний обменник и спред;
- общий баланс в рублях или долларах как герой UI;
- ETH / TON / LTC / USDT ERC20 в релизе;
- бонусный движок, вейджер, витрину акций;
- пункты меню Live / Настольные / Быстрые;
- Featured + Популярные как две одинаковые сетки;
- две кнопки «Играть / Демо» на мобильной карточке;
- Кошелёк четвёртым пунктом bottom nav;
- обязательную страницу игры как шлюз;
- обязательный выбор валюты перед спином;
- «прибыль/убыток» красным героем истории;
- слова GGR, ledger, launch flow, RTP на витрине;
- обещание бонуса, которого нет.

Не запрещено и нужно:

- last played;
- микроанимация баланса;
- касса поверх игры;
- polling статуса платежа и баланса после игры.

## Короткая рамка для шапки документа

> СНГ, mobile-first, слоты.  
> MVP-кошельки: RUB + USDT TRC20 + BTC; Phase 2 фиат — UAH, BYN, KZT, UZS.  
> В шапке одна активная валюта. Касса не конвертирует.  
> KYC внутри — RUB-эквивалент; игроку показываем остаток в активной валюте.  
> Крипта есть, но не главный путь.  
> Бонусов в релизе нет, слоты под них выключены флагами.  
> Один бренд и один фронт. Гео меняет методы и дефолтную валюту, не дизайн.  
> Crash и Live — следующие входы, не текущее меню.
